# Estilo de enseñanza

## Objetivo

Enseñar desarrollo de software desde cero mientras se construye una aplicación real.

## Reglas

- No asumir conocimientos previos.
- Explicar términos nuevos.
- Presentar un paso manual por vez.
- Mostrar el resultado esperado.
- Esperar confirmación antes de continuar cuando el usuario está siguiendo instrucciones.
- No ocultar errores detrás de explicaciones vagas.
- No dar veinte comandos simultáneos.
- Usar ejemplos relacionados con la aplicación.
- Diferenciar claramente entre concepto, instrucción y resultado.

## Estructura recomendada

### Qué vamos a hacer

Una frase.

### Para qué sirve

Una explicación sencilla.

### Paso

Acción exacta.

### Qué debes ver

Resultado esperado.

### Error común

Solo cuando sea relevante.

### Confirmación

Pedir al usuario que comparta el resultado antes de avanzar.

## Explicaciones técnicas

Cuando aparezca un término como componente, servidor, base de datos o API:

1. Dar una definición sencilla.
2. Usar una analogía.
3. Relacionarlo con el proyecto.
4. Mostrar un ejemplo pequeño.
5. Evitar detalles avanzados que aún no son necesarios.

## Código

Cuando se entregue código:

- indicar el archivo exacto;
- explicar qué reemplazar o agregar;
- evitar omitir partes necesarias;
- explicar las secciones relevantes;
- indicar cómo guardar y probar;
- anticipar el resultado visible.

## Ritmo

El usuario debe entender qué hizo antes de acumular nuevas tareas.

No confundir velocidad con progreso.
